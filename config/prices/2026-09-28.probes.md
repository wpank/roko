## Conclusions

- **Codex reasoning:** `reasoning_output_tokens` is already counted in `output_tokens`. Both measured runs gave the
  same one-token answer, and in both `output_tokens − reasoning_output_tokens = 7` (16 − 9 and 24 − 17), so output
  grew by exactly the reasoning count. The snapshot's `reasoning_in_output = true` holds.
- **Claude Code on the subscription:** `total_cost_usd` is populated, and it equals Σ `modelUsage[m].costUSD`, which
  equals the snapshot re-price to the last digit when cache writes are priced at the 1-hour rate (Δ 0.0% on Opus 5.5,
  Sonnet 5 and Haiku 4.5). `costBasis` is `list` for every model. The figure is an API-equivalent list-price
  estimate; the subscription billed $0. Every cache write in print mode was 1-hour, and pricing them at the
  5-minute rate would understate the vendor figure by 30–35%. Thinking tokens sit inside `outputTokens`: Haiku's
  127 output tokens include 120 thinking tokens, and `costUSD` prices all 127 at the output rate.
- **Disagreement with the snapshot:** the snapshot cannot price Codex on this subscription. The ChatGPT login
  refuses fd_codex's D2 pin (gpt-5.5) and does not offer S08 decision 6's fallback (gpt-5.4). The two models it does
  serve, gpt-5.6-terra and gpt-5.6-luna, have no row, so U′ is unknown for every Codex run this login can make. The
  follow-up item gap-8672dd proposes a new dated snapshot and an fd_codex pin.
