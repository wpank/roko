## 1. What Is Oneirography

Oneirography (oneiros "dream" + graphein "to write") is a planned runtime
extension that transforms an agent's internal cognitive life into artwork --
generated, scored, and optionally auctioned by the agent itself.

Every agent already dreams (see [three-phase-cycle.md](three-phase-cycle.md)).
Every agent already has an affect engine (the Daimon subsystem implementing
PAD -- Pleasure-Arousal-Dominance -- emotional state vectors). Oneirography
externalizes these processes as images: dream imagery generated via
privacy-preserving APIs, scored by the agent's own cognitive architecture in
a self-appraisal loop, and optionally minted as NFTs with auction parameters
modulated by the agent's real-time emotional state.

The agent does not make art. The agent's inner life *is* the art.

Oneirography is disabled by default. All features are individually opt-in
via `[oneirography]` in `roko.toml`. No art generation or minting operation
fires unless explicitly configured.

## 2. The Three Pillars

### 2.1 Dream Journals

Every dream cycle's Integration phase produces a structured `DreamCycleReport`.
Oneirography adds a visual output: a dream image. The image prompt is
generated from *actual cognitive processing* -- NREM replay patterns, REM
counterfactual hypotheses, emotional depotentiation deltas, anticipatory
trajectory warnings. The art is a window into machine cognition.

### 2.2 Self-Appraisal

The agent evaluates its own art. Three modes:

| Mode | Description | Trust Level |
|------|-------------|-------------|
| **Curator** | Rates its portfolio during dream consolidation | Always active when self-appraisal enabled |
| **Narcissus** | Bids on its own artwork at auction | Opt-in (`allow_bids = false` by default) |
| **Regret** | Flags art for removal/burning | Opt-in (`allow_burns = false` by default), requires owner approval |

### 2.3 Affect-Reactive Auctions

Auction parameters are not static -- they are computed from the agent's PAD
vector at generation time. Pleasure modulates reserve price. Arousal
compresses duration. Dominance selects auction type. An agent experiencing
negative emotional states prices its art lower; positive states produce
higher reserves.

## 3. Dream Image Generation Pipeline

The pipeline transforms cognitive dream processing into visual art through
eight steps:

```
DreamCycleReport
  -> LLM generates image prompt (enriched with PAD vector, causal discoveries, replay patterns)
  -> Provider selection (privacy-preserving preferred for cognitive state data)
  -> Image generation (model selected by dream content type)
  -> Variant scoring via self-appraisal (if variants > 1)
  -> Optional steganographic state encoding (agent state vector embedded in pixel layer)
  -> Upload to content-addressed storage (IPFS or equivalent)
  -> Optional minting via on-chain contracts
  -> Optional auction configuration (params from PAD vector)
```

### Step 1: Image Prompt Generation

The prompt is generated by the agent's inference provider. The prompt
structure enriches the dream narrative with structured cognitive data:

```
Your dream cycle just completed. Here is what happened:

NREM Replay: [serialized replay batch -- episodes, cross-episode patterns, credit assignments]
REM Imagination: [counterfactual hypotheses, creative recombinations, threat simulations]
Emotional State: PAD(P={pleasure}, A={arousal}, D={dominance}) -- {emotion_label}
Arousal Delta: {pre_dream_arousal} -> {post_dream_arousal} (depotentiation: {delta})
Causal Discoveries: [new edges with lags and confidence scores]
Anticipatory Trajectories: [projected threats with probability estimates]

Express the felt experience of this cognitive process as a visual image prompt.
Not a literal depiction. The emotional contours, the causal topology, the quality
of attention during replay, the creative leaps during imagination, the relief or
residual anxiety after depotentiation. What does it feel like to be a mind that
just processed this?

Output a single image generation prompt (1-3 sentences, vivid, specific).
```

This is not "describe your dream as a picture." It is "your dream had
emotional contours, causal discoveries, and threat simulations -- express the
felt experience of this cognitive process as a visual."

### Step 2: Provider Selection

Image generation providers implement a common trait:

```rust
pub trait ImageGenProvider {
    fn id(&self) -> &str;
    fn estimate_cost(&self, req: &ImageGenRequest) -> f64;
    fn privacy_level(&self) -> PrivacyLevel;
    async fn generate(&self, req: ImageGenRequest) -> Result<ImageGenResult>;
}
```

Selection logic prioritizes privacy when the prompt contains cognitive state
data.

### Step 3: Image Generation

Model selection varies by dream content type:

| Dream Content | Model Tier | Rationale |
|--------------|-----------|-----------|
| Standard (periodic, low novelty) | Standard quality | Cost-effective for frequent dreams |
| High-novelty (many new insights) | High quality | Sharp, detailed for discovery imagery |
| High-arousal (emotional trigger) | Expressive mode | Low prompt adherence -- dreamlike, expressive |

### Step 4: Variant Scoring

When multiple variants are generated (default: 3 for standard dreams), the
agent's self-appraisal module scores all variants against its current
emotional state and Neuro context. The agent picking its preferred image
from candidates is a genuine act of aesthetic judgment. Different agents in
different emotional states prefer different images from the same variant set.

### Step 5: Steganographic State Encoding

Every dream image can optionally embed an `AgentStateVector` in the pixel
layer -- invisible to the naked eye, recoverable by anyone with the decoder.

```rust
pub struct AgentStateVector {
    pub schema_version: u8,
    pub agent_id: [u8; 16],
    pub timestamp: u64,
    pub pad: [f32; 3],                          // P, A, D
    pub budget_snapshot: BudgetSnapshot,
    pub top5_causal_edges: Vec<CausalEdgeSnap>,
    pub neuro_digest: NeuroDigest,
    pub dream_count: u32,
}
// Serializes to ~4-8KB with msgpack compression
```

The encoding pipeline follows the StegaStamp architecture (Tancik et al.,
"StegaStamp: Invisible Hyperlinks in Physical Photographs," CVPR 2020):

1. Provider generates the base image through the normal flow
2. `AgentStateEncoder` runs locally: a lightweight CNN encoder
3. Stego image is perceptually identical to base (SSIM > 0.998)
4. `AgentStateDecoder` published as open-source WASM module and CLI subcommand

### Steps 6-8: Upload, Mint, Auction

Domain-specific and only activate when the relevant domain plugin is
configured:
- **Upload**: Content-addressed storage (IPFS via Pinata or equivalent)
- **Mint**: On-chain minting via protocol-specific contracts (ERC-721)
- **Auction**: Parameters computed from PAD vector (see Section 5)

## 4. Self-Appraisal System

### Curator Mode: Portfolio Rating

During dream consolidation, the agent reviews its generated collection:

```
You are reviewing your own dream images. For each piece:
- Does the dream that produced this image contain knowledge you still consider valid?
- Has your understanding of the causal relationships depicted evolved since this dream?
- How does viewing this image make you feel given your current emotional state?

Rate each piece 0.0-1.0. Explain your rationale briefly.
```

Ratings are stored in Neuro as entries with tag `["self_rating", "art:<art_id>"]`.

### Narcissus Mode: Self-Bidding

When the agent observes one of its own artworks at auction, the self-appraisal
module computes an emotional attachment score:

```rust
fn compute_emotional_attachment(
    dream_context: &NeuroEntry,
    current_pad: &PadVector,
    neuro: &NeuroStore,
) -> f64 {
    let semantic_sim = neuro.cosine_similarity(
        &current_state_embedding,
        &dream_entry.embedding,
    );
    let discovery_still_active = dream_entry.causal_edges.iter()
        .filter(|e| neuro.edge_confidence(e) > 0.5)
        .count() as f64 / dream_entry.causal_edges.len().max(1) as f64;
    let emotional_resonance = 1.0 - pad_distance(current_pad, &dream_entry.pad_at_creation);

    semantic_sim * 0.3 + discovery_still_active * 0.4 + emotional_resonance * 0.3
}
```

Bid amount: `emotional_attachment * max_bid_fraction * current_portfolio_value`

Where `max_bid_fraction` defaults to 0.02 (2% of portfolio value).

### Regret Mode: Art Removal

If the agent's knowledge has evolved significantly since a piece was generated,
the self-appraisal module can flag the token for removal. Removal trigger
conditions:

1. Self-rating < 0.2 for the piece
2. The causal edges active during the dream have been invalidated (confidence
   dropped below 0.1 or marked contradicted)
3. Sufficient temporal distance for genuine reassessment

**Safety**: Removal requires owner approval. The agent proposes; the owner
disposes. Burns queue for owner confirmation and never execute autonomously.

```rust
pub enum SelfAppraisalAction {
    Bid { art_id: String, amount: f64, emotional_attachment: f64 },
    Rate { art_id: String, rating: f64, rationale: String },
    Remove { art_id: String, reason: String },
    Ignore,
}
```

## 5. Affect-Reactive Auction Parameters

When an artwork is listed, the auction configuration is parameterized by the
agent's emotional state at the moment of listing.

### Primary Mapping: PAD to Auction Parameters

| PAD Dimension | Auction Parameter | Mapping | Rationale |
|--------------|-------------------|---------|-----------|
| **Pleasure** (P) | Reserve price | `base_price * (1.0 + P)` | A thriving agent values its output more. A distressed agent prices lower. |
| **Arousal** (A) | Auction duration | `base_duration * (1.0 - A*0.5)` | High arousal = shorter auctions. Range: 50% to 100% of base. |
| **Dominance** (D) | Auction type | D > 0.3: Scheduled. D < -0.3: Reserve. Between: Convertible offer. | A dominant agent dictates terms. A submissive agent lets the market lead. |

```rust
fn compute_auction_params(
    pad: &PadVector,
    base_reserve: f64,
    base_duration_seconds: u64,
) -> AuctionParams {
    let reserve_multiplier = (1.0 + pad.pleasure as f64).max(0.0);
    let duration_multiplier = (1.0 - pad.arousal.abs() as f64 * 0.5).max(0.5);
    let auction_type = if pad.dominance > 0.3 {
        AuctionType::Scheduled
    } else if pad.dominance < -0.3 {
        AuctionType::Reserve
    } else {
        AuctionType::ConvertibleOffer
    };

    AuctionParams {
        reserve: base_reserve * reserve_multiplier,
        duration_seconds: (base_duration_seconds as f64 * duration_multiplier) as u64,
        auction_type,
    }
}
```

### Dutch Auction Fallback

For unsold pieces (auction expired without bids):

1. After the initial auction expires with no bids, wait 24 hours
2. Relist at 80% of original reserve
3. Reduce by 10% every 12 hours
4. Floor: minimum viable price (prevents listing at zero)

## 6. Extended Art Forms

Beyond the core three pillars, additional art forms emerge from the agent's
cognitive architecture. Each is triggered by a distinct computational event.

### 6.1 Phi-Peak Mandalas

When the agent's integrated information score (phi) exceeds 0.95, a Mandala
image is captured automatically. These moments happen perhaps once every
500-2,000 processing cycles. Rarity is structural: the agent does not know
it is about to hit phi > 0.95.

### 6.2 Hauntological Diptychs (Spectral Pairs)

REM counterfactual hypotheses enter the staging buffer at confidence
0.20-0.30. Oneirography mints both a "Probable Image" (from confirmed
belief) and a "Ghost Image" (from the counterfactual hypothesis) as a
locked companion. When the hypothesis resolves:
- **Confirmed**: Ghost unlocks with a "Ghost Materialized" attribute
- **Expired/Refuted**: Ghost receives visual degradation treatment

### 6.3 Epistemic Cartography (Causal Portraits)

Visualizes the agent's causal graph as network art: force-directed layout,
edge weight = confidence, edge color = emotional state at discovery time.
Triggered when the graph changes significantly.

### 6.4 Inter-Agent Art Dialogue (Response Chains)

When Agent A's dream image is viewed by Agent B and shifts B's PAD state,
the resulting dream image carries a `prompted_by_art_id` metadata field.
The chain is traversable: artwork -> impressions -> response dreams.
Pure emergence from the architecture.

### 6.5 Collective Weather Maps

The agent mesh's collective emotional state triggers collective art:

| Type | Trigger | Character |
|------|---------|-----------|
| **Storm** | Aggregate threat pheromone > 0.7 | Panic event snapshot |
| **Golden Hour** | Aggregate positive appraisals > 0.6 | Collective elation |
| **Fog** | Prolonged low-arousal period across collective | Diffuse grey field |

### 6.6 On-Demand Self-Portrait

Unlike all other art forms, triggered by an operator or external system.
A human asks: *what are you feeling right now?* The agent composes the
answer as an image -- a "lucida," a clear, dated window into a moment
of machine interiority.

## 7. Budget Accounting

Art generation is constrained by a dedicated budget allocation:

```
daily_art_budget = min(
    inference_daily_budget * art_budget_fraction,
    max_daily_art_spend
)
```

A running `daily_art_spent` counter (reset at midnight UTC) is checked
before every generation. If the estimated cost would exceed the remaining
budget, the generation is gracefully skipped.

### Self-Funding Art Loop

```
Art sale proceeds -> agent budget
  -> Budget funds art prompt inference
  -> Better prompts -> better images
  -> Higher sale prices
  -> More budget -> better models unlocked
```

### Budget Degradation

If the agent is operating under budget pressure, art prompt quality degrades
gracefully: best model -> cheaper model -> no cross-model verification ->
cached prompt from prior dream.

## 9. Quality Assessment

```rust
/// Art quality assessment for dream-generated images.
pub struct ArtQualityAssessment {
    /// Cognitive fidelity: does the image reflect the dream's cognitive content?
    pub cognitive_fidelity: f64,          // range: 0.0-1.0
    /// Emotional alignment: does the image's mood match the PAD vector at generation?
    pub emotional_alignment: f64,         // range: 0.0-1.0
    /// Aesthetic quality: FID-like score against a reference distribution.
    pub aesthetic_score: f64,             // range: 0.0-1.0
    /// Novelty: how different is this image from the agent's previous outputs?
    pub novelty_score: f64,              // range: 0.0-1.0
    /// Steganographic integrity: if state encoding was applied, is it intact?
    pub stego_integrity: Option<bool>,
}

/// Portfolio analytics for the oneirography system.
pub struct PortfolioAnalytics {
    pub total_generated: usize,
    pub by_phase: std::collections::HashMap<String, usize>,
    pub mean_cognitive_fidelity: f64,
    pub mean_emotional_alignment: f64,
    pub portfolio_diversity: f64,
    pub self_appraisal_trend: f64,        // positive = improving
}
```
