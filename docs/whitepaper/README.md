## Thesis

Golden path plus cybernetics. A frontier model plans; cheap models execute granular tasks in parallel on a DAG,
in worktrees; gates and a whole-plan check verify the result; and feedback loops make the system improve
measurably. The paper describes this ideal state and tags every mechanism with its status at a commit, so that a
reader can tell what runs today from what is only designed. Much of it is only designed so far, and the
cheap-model half of the thesis is untested on real work: every portal task ran on one pinned model (§4.12, §7).

## Conventions

### Status header

Line 1 of every section file (`NN-*.md` and `appendix-*.md`) is its status header:

    Status: stub · budget 550 words · owner gap-353d57

- **State:** `stub` (this outline's placeholder), `draft` (written and lint-clean) or `reviewed` (set by the
  review, gap-8d2c79). `paperlint --strict` fails on `stub`, and the epic's exit check requires `reviewed`.
- **Budget:** the number in the Outline table. `--strict` fails below half of it or above 1.3 times it. The count
  covers the words after the header, tables and captions included, and leaves out fenced blocks and footnote
  definitions. The appendix's header says `budget none`.
- **Owner:** the work item that writes the file.
- `build.sh` strips the header from the PDF.
- This README and `REVIEW.md` carry the same header with `budget none`, so that `paperlint --strict` checks every
  Markdown file in this directory.

### Voice and tense

- The ideal-state voice with honest tags: describe the design, and put its status tag in the same sentence or
  table row.
- §0, §1, §8 and §10, the parts people quote, say "is designed to" for anything that is not `WIRED`.
- Never claim an effect without evidence. A result that doesn't exist yet is called pending, with the item that
  will produce it.
- Give the setting of every literature result (single function, QA, documents or repository scale), so that no
  result reads as broader than it is.
- Numbers carry denominators. Use plain mechanism names (see the word list below).

### Status tags

- Write a tag as `TAG@<sha>`, e.g. `PARTIAL@a17d4dadd`: the tag in capitals, `@`, and a short sha of at least 7 hex
  digits (use the 9 that `git log --oneline` prints). The commit must be an ancestor of HEAD.
- Take tags from the status matrix (the appendix, rendered from `data/mechanisms.toml`) at its pinned commit, never
  from older notes: several mechanisms moved in the merges of 2026-09-29.
- Every mechanism that is not `WIRED` also names the item or epic that would change its tag.
- The vocabulary:

| Tag | Meaning |
|---|---|
| `WIRED` | Runs on the production path (`roko plan run`, `roko run`) and does its job: a sensor records, a regulator changes behaviour |
| `PARTIAL` | On the path, but incomplete, masked or fed wrong data |
| `ORPHANED` | Worked under Runner-v2 (deleted 2026-09-06 in `6b5da8616`) and was not re-attached |
| `BUILT-UNWIRED` | Code and tests exist, with no production caller |
| `DOCS-ONLY` | `docs/` describes it as working, but there is no meaningful code |
| `MISSING` | Not built; it may already be specified |
| `REMOVED` | Deliberately deleted |
| `BROKEN` | Wired, but does the wrong thing |
| `UNPROVEN` | Might be true; no measurement exists |

### Markers

The research draft's marker grammar. Markers belong in stubs and drafts in progress:
`paperlint --strict` fails on any `[[…]]` left outside code, so a finished section has none.

| Marker | Meaning |
|---|---|
| `[[TODO: …]]` | Work still to do |
| `[[CITE?: …]]` | A claim still missing its source; never ship one |
| `[[AS-BUILT: …]]` | Design text still to check against the code |
| `[[RESULT …: …]]` | A result that must come from an experiment. A finished section replaces it with a sentence saying the result is pending, and naming the item that will produce it |

TOML table names such as `[[task.verify]]` inside code spans are not markers.

### Citations and sources

- **Literature:** `[@key]`, with the key in `references.bib`. Check each new key's identifier before adding it (an
  arXiv id through DataCite, a DOI through Crossref), note it in the entry's comment, and add keys in a small commit
  of their own.
- **Vendor pages:** an `@online` entry with its `urldate`. A vendor's numbers stay the vendor's claims.
- **The repository:** tracked files and commits only. Write a repo path from the root in backticks
  (`crates/roko-graph/src/engine.rs`) and its symbol as a separate code span (`plan_to_graph`); avoid line
  numbers, which drift. Write a commit as a 9-digit short sha in backticks. Cite a work item by its id, e.g.
  spec-6ac537.
- **Gitignored inputs** (the tldr, the research notes, the programme specs S01–S11, the field evidence and the
  research draft) are never cited directly. Cite the tracked epic or item that carries them, or freeze the part
  you quote into `evidence/`.

### Numbers and footnotes

- Every paragraph, list item or table with a `$` amount, a percentage, an `N×` ratio, an "N of M" count or an
  `N/M` fraction has a footnote in the same block. Its definition names the source: a commit, a work item id, a
  `[@key]`, or a rollup or snapshot with its id (e.g. "rollup 2026-09-29T14:37:51") together with the frozen file
  in `evidence/` that holds it. An inline `[@key]` also counts. The footnote also gives the window or scope.
- Footnote labels start with the section number, because `build.sh` joins the files: `[^7-portal]`.
- `paperlint` counts a footnote as a source only when it names a commit, a work item, a `[@key]` or a rollup or
  snapshot id. A frozen file cited by its sha256 alone does not count, so name the item that froze it as well.
- For example:

```markdown
Roko built most of the portal: 16 plans and 173 tasks for $174.87 of recorded agent spend.[^7-portal]

[^7-portal]: Rollup <id>, frozen as `evidence/<date>-<slug>.json` (sha256 `<first 12 hex digits>`), keys
    `…`. Portal plans only, attempts to 2026-09-29 07:41Z; the supervising sessions are excluded.
```

### Frozen evidence

Anything quoted from a gitignored source is copied into `evidence/` and fixed there by its hash. gap-29a64e (§7)
creates the directory; other sections add files in small commits of their own.

- **Only derived, scrubbed data:** counts, rollups, tables and case write-ups. Never transcripts, prompts,
  environment dumps, or anything that could hold a key (bug-7d7200).
- **Names:** `evidence/<YYYY-MM-DD>-<slug>.<ext>`, dated by when the source generated it.
- **Hashes:** `evidence/SHA256SUMS` holds one `shasum -a 256` line per file. Check them with
  `cd docs/whitepaper/evidence && shasum -a 256 -c SHA256SUMS`.
- **Provenance:** `evidence/README.md` has one row per file: its source path, the tool and time that generated it,
  the commit it describes, its window, and what was removed from it.
- **Never edit a frozen file.** To refresh one, freeze a new dated file and update the footnotes that cite it.
- A footnote names the rollup or snapshot with its id, the frozen file with the first 12 hex digits of its
  sha256, and the key or row it quotes.

### Code identifiers

- Every backticked identifier or repo path must exist at HEAD (`git grep -w`, `git ls-files`).
- A designed name that doesn't exist yet gets (designed), as plain text, in the same sentence as its first use in
  each file; later uses in that file are then covered. A `[[AS-BUILT: …]]` marker also exempts a name, but
  `--strict` fails on any marker. The research draft's §4 used eight such names: don't carry them over unmarked.
- docs/v3 is not evidence: its headline claims were checked against the code, and several failed (§3.3).

### Headings

### Banned words

- **Banned:** `provably`, `self-aware`, `metacognitive`, `flywheel`, `autocatalytic`, `superlinear`, `first-of-its-kind`, `is the first`, `the first to`, `world's first`, `immune`, `dream`, `dreams`, `dreaming`, `hypnagogia`, `daimon`, `somatic`, `demurrage`, `cortical`, `pheromone`, `pheromones`.

| `metacognitive` | "calibrated self-model" (M3) |
| `flywheel` | "measured, guarded improvement" |
| `autocatalytic` | "bounded, audited improvement" |
| `superlinear` | The measured effect, or nothing |
| `first-of-its-kind` | "as documented on 2026-09-29, we found no product that …" |
| `is the first` | As above |
| `the first to` | As above |
| `world's first` | As above |
| `immune` | "output screening" |
| `dream` | "offline batch consolidation" |
| `dreams` | "offline batch consolidation" |
| `dreaming` | "offline batch consolidation" |
| `hypnagogia` | "offline batch consolidation" |

## Building the PDF

`build.sh` (gap-8117a8) builds the PDF from this directory alone. pandoc joins the sections in the outline's order
without their status headers, resolves the citations against `references.bib` and writes LaTeX; librsvg converts
the figures, and tectonic typesets the result. Install the tools with `brew install pandoc tectonic librsvg`;
tectonic downloads its LaTeX packages on its first run.

```sh
docs/whitepaper/build.sh            # writes tmp/whitepaper/roko-whitepaper.pdf (tmp/ is gitignored)
docs/whitepaper/build.sh out.pdf    # or a path you choose
```

- **Checks:** any pandoc warning fails the build, so an unknown citation key stops it.
- **Reproducible:** the PDF's dates are the commit time of the sources, so one commit built with the same pandoc,
  tectonic and librsvg gives the same bytes. The script ends by printing the PDF's sha256. It needs no git
  metadata, so it also builds from an export: `git archive <tag> docs/whitepaper | tar -x -C <dir>`.
- **Don't commit the PDF:** a release carries it.
