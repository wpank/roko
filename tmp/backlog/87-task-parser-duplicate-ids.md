# 87 — Task Parser Does Not Detect Duplicate Task IDs

**Priority**: P0 — correctness (silent data loss: one of two tasks with the same ID is silently dropped)
**Size**: S (2-3 hours)
**Crates**: `crates/roko-cli` (`src/task_parser.rs`)
**Depends on**: None

---

## Background

`tasks.toml` uses a TOML array of tables (`[[task]]`) to define the list of tasks in a plan. TOML allows multiple `[[task]]` entries with the same `id` field — it does not enforce uniqueness. The task parser loads all entries into a `Vec<TaskDef>` without checking for duplicates.

This matters because `tasks.toml` files are frequently generated by LLM agents, which can produce duplicate IDs (for example, two `[[task]]` blocks both with `id = "T01"`). When a duplicate occurs, downstream code that uses `HashSet` or `HashMap` over the task list silently drops one of the two tasks. The `parallel_groups` method at line 746 skips tasks by ID via `assigned.contains_key`, so the second task with a duplicate ID is never scheduled. The `validate_structure` function at line 957 builds a `HashSet` from task IDs, but never checks whether the set is smaller than the vector. No error is ever surfaced.

The fix requires two additions to `validate_structure`: detect when the set size differs from the vec size, and when it does, identify which specific IDs are duplicated. A new `DuplicateId` variant must be added to the `TaskValidationIssue` enum. Additionally, task IDs that are empty strings or contain control characters or whitespace should also be rejected since they cannot be safely used as map keys.

### Step 3: Add duplicate detection in `validate_structure`

After line 959 in `validate_structure` (where `task_ids` is built), add the size comparison and duplicate finder:

```rust
if task_ids.len() != self.tasks.len() {
    let mut seen: HashSet<&str> = HashSet::new();
    for task in &self.tasks {
        if !seen.insert(task.id.as_str()) {
            issues.push(TaskValidationIssue::DuplicateId(task.id.clone()));
        }
    }
}
```

This uses a second pass to identify the specific IDs that appear more than once. It only reports each duplicate ID once (on its second occurrence), which is enough information for the caller to fix the problem.
