## Problem

Two plan-generator layers outlived the one pipeline that replaced them, and nothing in production calls either:

- `crates/roko-cli/src/plan_generator.rs`: `DefaultPlanGenerator`, a validation pipeline that only its own tests
  exercise. Plans are generated by `roko_cli::plan_generate::generate_plan` (gap-2623b2), the one generator
  `roko run`, `roko plan generate`, regeneration and serve use.
- `crates/roko-execution/src/plan_generator.rs`: the value types (`PlanGeneratorRequest`, `PlanGeneratorAdapter`,
  `PlanGeneratorOutcome`, `ValidatedPlan`, `ValidationEvidence`, `PlanSource`, …), re-exported from
  `roko-execution/src/lib.rs`, used only by `DefaultPlanGenerator`. Its `adapter_keys` manifest names call sites
  that no longer exist: `PRD_DEFAULT`, `PRD_MODEL` and `PRD_REPLAN` (`prd.rs::generate_plan_from_prd*`),
  `DO_STANDARD` and `DO_COMPLEX` (`commands/do_cmd.rs`), and `CLI_SERVE_RUNTIME`/`SERVE_RUNTIME`
  (`generate_plan_from_prd`, now `generate_plan_from_prompt`). The PRD pipeline, `roko do` and `do_cmd.rs` were
  removed on 2026-10-02 (`tmp/workflow-audit/`).

## Why it matters

Dead code that names removed commands misleads readers and searches ("CHECK FIRST" in CLAUDE.md), and a second
`PlanSource` type in roko-execution sits next to the live `roko_cli::plan_generate::PlanSource`.

## Where

- `crates/roko-cli/src/plan_generator.rs` (`DefaultPlanGenerator`, `adapter_keys_manifest_complete` test)
- `crates/roko-execution/src/plan_generator.rs` (`adapter_keys`, value types) and its re-export in
  `crates/roko-execution/src/lib.rs`
- `crates/roko-cli/src/plan_generate.rs` (`PlanTemplateKind` doc names `DefaultPlanGenerator`'s tests)

## Current state

PK32 (gap-b5caf3) and PK74 (gap-ce1d11) list `crates/roko-cli/src/plan_generator.rs` among the files they change,
so the workflow-audit migration left both files in place.

## Plan

1. After PK32 and PK74 land, check whether either now calls `DefaultPlanGenerator`. If not, delete
   `crates/roko-cli/src/plan_generator.rs` and the roko-execution value types it alone uses.
2. If something does use them, keep the types but delete the stale `adapter_keys` rows (PRD and `roko do` paths)
   and point the module docs at `plan_generate::generate_plan`.
